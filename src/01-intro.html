🎯 เมื่อเรียนจบบทนี้ นิสิตจะสามารถ
  1. อธิบายความหมายของข้อมูล สารสนเทศ ฐานข้อมูล และระบบฐานข้อมูลได้
  2. วิเคราะห์ปัญหาของการจัดเก็บข้อมูลด้วยระบบแฟ้มข้อมูลแบบเดิมได้
  3. อธิบายหน้าที่และองค์ประกอบของระบบจัดการฐานข้อมูล (DBMS) ได้
  4. อธิบายสถาปัตยกรรม 3 ระดับ และความเป็นอิสระของข้อมูลได้
  5. จำแนกแบบจำลองข้อมูล ระบุบทบาทบุคลากร และอธิบายวงจรการพัฒนาระบบฐานข้อมูลได้

1.1 ข้อมูล สารสนเทศ และฐานข้อมูล

ทุกองค์กรในปัจจุบันขับเคลื่อนด้วยข้อมูล — มหาวิทยาลัยเก็บข้อมูลการลงทะเบียน ธนาคารเก็บรายการเคลื่อนไหวของบัญชี ร้านค้าออนไลน์เก็บคำสั่งซื้อ ก่อนจะจัดเก็บข้อมูลอย่างเป็นระบบ ต้องแยกคำ 3 คำนี้ให้ออก

ข้อมูล (Data)60001, Rukawa, 3.75
→ ประมวลผล →
สารสนเทศ (Information)“Rukawa มี GPA 3.75 สูงกว่าค่าเฉลี่ยสาขา”
→ วิเคราะห์ →
ความรู้ (Knowledge)“ควรให้ Programming เป็นวิชาบังคับก่อน Database”
  • ข้อมูล (Data) ข้อเท็จจริงที่ยังไม่ผ่านการประมวลผล อาจเป็นตัวเลข ตัวอักษร ภาพ เสียง — ลำพังยังใช้ตัดสินใจไม่ได้
  • สารสนเทศ (Information) ข้อมูลที่ผ่านการประมวลผล สรุป หรือตีความจนมีความหมาย ใช้ประกอบการตัดสินใจได้
  • ความรู้ (Knowledge) สารสนเทศที่วิเคราะห์ร่วมกับประสบการณ์จนเกิดเป็นแนวทางปฏิบัติ

ฐานข้อมูล (Database) คือกลุ่มของข้อมูลที่มีความสัมพันธ์กัน จัดเก็บอย่างเป็นระบบในที่เดียว มีโครงสร้างกำหนดไว้ล่วงหน้า เพื่อให้ผู้ใช้และโปรแกรมหลายตัวใช้ข้อมูลร่วมกันได้ — หัวใจของฐานข้อมูลจึงไม่ใช่ “ข้อมูลเยอะ” แต่คือ “ความสัมพันธ์และการใช้ร่วมกัน”

ระบบฐานข้อมูล (Database System) คือระบบโดยรวม ได้แก่ ตัวฐานข้อมูล + ซอฟต์แวร์ DBMS + ฮาร์ดแวร์ + บุคลากร + ขั้นตอนการปฏิบัติงาน

📝 ข้อสังเกต

ไฟล์ Excel ที่เก็บรายชื่อนิสิตแผ่นเดียว ยังไม่นับเป็น “ฐานข้อมูล” ในความหมายทางวิชาการ เพราะไม่มีโครงสร้าง (Schema) และความสัมพันธ์ที่ชัดเจน

จงระบุว่าแต่ละข้อเป็น ข้อมูล หรือ สารสนเทศ

  3. 'F'
  4. “นิสิตสาขา Physics มีเกรดเฉลี่ยรวม 2.70”
  1. ข้อมูล — เป็นรหัสวิชาเดี่ยว ๆ ยังไม่มีความหมายเพื่อการตัดสินใจ
  2. สารสนเทศ — ได้จากการนับ (ประมวลผล) ข้อมูลการลงทะเบียน
  3. ข้อมูล
  4. สารสนเทศ — ได้จากการหาค่าเฉลี่ย

1.2 ระบบแฟ้มข้อมูลแบบเดิม และปัญหาที่เกิดขึ้น

ก่อนมีแนวคิดฐานข้อมูล แต่ละหน่วยงานหรือโปรแกรมจะสร้าง แฟ้มข้อมูลของตัวเอง แยกกัน (File-processing System) ดังภาพ (a) ส่วนแนวคิดฐานข้อมูลรวมข้อมูลไว้ส่วนกลาง และให้ทุกโปรแกรมเข้าถึงผ่าน DBMS ดังภาพ (b)

เปรียบเทียบระบบแฟ้มข้อมูล (a) กับแนวคิดฐานข้อมูล (b)
ปัญหาความหมาย / ตัวอย่าง
Data Redundancy
ความซ้ำซ้อน		ชื่อ-ที่อยู่นิสิตถูกเก็บซ้ำทั้งในแฟ้มทะเบียน การเงิน ห้องสมุด สิ้นเปลืองเนื้อที่

ความไม่สอดคล้อง		แก้ที่อยู่ที่งานทะเบียนแล้ว แต่ห้องสมุดยังส่งจดหมายไปที่อยู่เดิม
Difficulty in Accessing
เข้าถึงยาก		อยากได้รายงานรูปแบบใหม่ ต้องให้โปรแกรมเมอร์เขียนโปรแกรมใหม่ทุกครั้ง
Data Isolation
ข้อมูลโดดเดี่ยว		ข้อมูลกระจายหลายแฟ้ม หลายรูปแบบ รวมข้ามแฟ้มทำรายงานยาก

ความคงสภาพ		กฎ “GPA ต้องอยู่ระหว่าง 0.00–4.00” ต้องเขียนตรวจในทุกโปรแกรม

Security Problemกำหนดสิทธิ์ได้แค่ “เปิดแฟ้มได้/ไม่ได้” เปิดได้ก็เห็นทุกคอลัมน์ทุกแถว

จงระบุชื่อปัญหาของระบบแฟ้มข้อมูลในแต่ละสถานการณ์

  1. ระบบแสดงยอดเงินในบัญชีไม่ตรงกันระหว่างแอปมือถือกับสาขาธนาคาร
  2. พนักงานฝ่ายบัญชีเปิดแฟ้มพนักงานเพื่อดูเลขบัญชี แต่เห็นเงินเดือนของทุกคนด้วย
  3. ผู้บริหารขอรายงาน “นิสิตที่ค้างค่าเทอมและยืมหนังสือเกินกำหนด” แต่ต้องรอ 2 สัปดาห์
  1. Data Inconsistency (มักเกิดจาก Data Redundancy)
  2. Security Problem
  3. Difficulty in Accessing Data และ Data Isolation (ข้อมูลอยู่คนละแฟ้ม คนละหน่วยงาน)

1.3 ระบบจัดการฐานข้อมูล (DBMS)

DBMS (Database Management System) คือซอฟต์แวร์ตัวกลางระหว่างผู้ใช้/โปรแกรม กับข้อมูลที่เก็บจริงบนดิสก์ ผู้ใช้ไม่ต้องรู้ว่าข้อมูลเป็นไฟล์อะไร อยู่ตรงไหน แค่ส่งคำสั่ง SQL แล้วรอรับผลลัพธ์

หน้าที่หลักของ DBMS

  1. Data Definition — กำหนดโครงสร้างตาราง ชนิดข้อมูล กฎบังคับ (คำสั่งกลุ่ม DDL)
  2. Data Manipulation — เพิ่ม ลบ แก้ไข แสดงข้อมูล (DML / DQL)
  3. Integrity Control — บังคับกฎ เช่น Primary Key, Foreign Key, CHECK
  4. Security Control — กำหนดสิทธิ์ระดับตาราง คอลัมน์ หรือวิว
  5. Concurrency Control — จัดลำดับและล็อกข้อมูลให้ผู้ใช้หลายคนทำงานพร้อมกันได้
  6. Backup & Recovery — บันทึก Log File เพื่อกู้คืนเมื่อระบบล้มเหลว
  7. Query Optimization — เลือกวิธีเข้าถึงข้อมูลที่เร็วที่สุด

1.4 องค์ประกอบของระบบฐานข้อมูล

องค์ประกอบ 5 ส่วนของระบบฐานข้อมูล
  1. Hardware — เครื่องแม่ข่าย ดิสก์ เครือข่าย เครื่องลูกข่าย
  2. Software — DBMS, ระบบปฏิบัติการ, โปรแกรมประยุกต์
  3. Data — ข้อมูลจริง + Metadata (ข้อมูลที่อธิบายข้อมูล เช่น ชื่อคอลัมน์ ชนิดข้อมูล) เก็บใน Data Dictionary
  4. People — บุคลากร (ตารางด้านล่าง)
  5. Procedure — ระเบียบปฏิบัติ เช่น ขั้นตอนขอสิทธิ์ การสำรองข้อมูลประจำวัน แผนกู้คืนระบบ

1.5 สถาปัตยกรรมของระบบฐานข้อมูล

สถาปัตยกรรม 3 ระดับ (ANSI-SPARC)

สถาปัตยกรรมสามระดับตามมาตรฐาน ANSI-SPARC
  1. External Level (ระดับภายนอก) — มุมมองของผู้ใช้แต่ละกลุ่ม เห็นเฉพาะข้อมูลที่เกี่ยวกับตน (ในทางปฏิบัติคือ View — บทที่ 7)
  2. Conceptual Level (ระดับแนวคิด) — มุมมองรวมทั้งองค์กร มีเอนทิตีใด แอตทริบิวต์ใด สัมพันธ์กันอย่างไร
  3. Internal Level (ระดับภายใน) — การจัดเก็บจริง เช่น รูปแบบไฟล์ ดัชนี การบีบอัด

🧩 Logical Data Independence

เปลี่ยนระดับแนวคิด (เช่น เพิ่มคอลัมน์ email ใน student) โดยโปรแกรมที่ใช้มุมมองเดิมไม่ต้องแก้

💾 Physical Data Independence

เปลี่ยนวิธีจัดเก็บ (เช่น สร้างดัชนีเพิ่ม ย้ายดิสก์) โดยระดับแนวคิดและโปรแกรมไม่ได้รับผลกระทบ

สถาปัตยกรรมไคลเอนต์-เซิร์ฟเวอร์

ในทางปฏิบัติ ฐานข้อมูลอยู่บนเครื่องแม่ข่าย และให้บริการโปรแกรมหลายตัวพร้อมกัน — เช่นในวิชานี้ DBeaver บนเครื่องนิสิต (client) เชื่อมไปยัง MySQL ที่ 202.28.34.202 (server)

สถาปัตยกรรมไคลเอนต์-เซิร์ฟเวอร์ของระบบฐานข้อมูล การไหลของข้อมูลในการพัฒนาซอฟต์แวร์และตำแหน่งของชั้นฐานข้อมูล

มหาวิทยาลัยต้องการให้อาจารย์เห็นเฉพาะรายชื่อนิสิตในกลุ่มเรียนที่ตนสอน การออกแบบนี้อยู่ระดับใดของสถาปัตยกรรม 3 ระดับ และหากต่อมามีการสร้างดัชนีบนคอลัมน์ stdid จะกระทบมุมมองของอาจารย์หรือไม่ เพราะเหตุใด

External Level — เป็นมุมมองเฉพาะกลุ่มผู้ใช้ (สร้างด้วย View)

การสร้างดัชนีเป็นการเปลี่ยนแปลงที่ Internal Level จึงไม่กระทบ มุมมองของอาจารย์ — นี่คือ Physical Data Independence

(ข) ระบบเก็บ log การคลิกของผู้ใช้เว็บวันละหลายสิบล้านรายการ ที่รูปแบบข้อมูลเปลี่ยนบ่อย

(ก) Relational — ข้อมูลมีโครงสร้างชัดเจน มีความสัมพันธ์ ต้องการกฎความคงสภาพและทรานแซกชัน

(ข) NoSQL — ปริมาณมาก โครงสร้างไม่คงที่ ต้องขยายระบบแนวนอน

1.7 ข้อดีและข้อจำกัดของระบบฐานข้อมูล

✅ ข้อดี

  • ลดความซ้ำซ้อนและความไม่สอดคล้อง
  • ใช้ข้อมูลร่วมกันได้หลายหน่วยงาน
  • บังคับใช้มาตรฐานและกฎจากส่วนกลาง
  • กำหนดสิทธิ์ได้ละเอียดถึงคอลัมน์
  • สำรอง/กู้คืนได้อย่างเป็นระบบ
  • รองรับผู้ใช้จำนวนมากพร้อมกัน

⚠️ ข้อจำกัด

  • ค่าใช้จ่ายฮาร์ดแวร์/ซอฟต์แวร์สูง
  • ต้องการบุคลากรเฉพาะทาง
  • ระบบซับซ้อน ออกแบบผิดกระทบวงกว้าง
  • เซิร์ฟเวอร์ล่ม ทุกหน่วยงานหยุดพร้อมกัน
  • ต้องบำรุงรักษาอย่างต่อเนื่อง
  • ย้ายระบบเดิมมีต้นทุนและความเสี่ยง

1.8 วงจรการพัฒนาระบบฐานข้อมูล

ขั้นตอนในวงจรการพัฒนาระบบฐานข้อมูล
ขั้นตอนสิ่งที่ทำเรียนในบท
1. Requirement Analysisเก็บความต้องการ ต้องเก็บข้อมูลอะไร ต้องการรายงานอะไร—
2. Conceptual Designเขียนแผนภาพ ERบทที่ 2
3. Logical Designแปลง ER เป็นตารางเชิงสัมพันธ์บทที่ 3
4. Normalizationปรับโครงสร้างลดความซ้ำซ้อนบทที่ 3

⚠️ ข้อควรระวัง

ความผิดพลาดที่พบบ่อยที่สุดของผู้เริ่มต้น คือ ข้ามขั้นตอนออกแบบแล้วสร้างตารางทันที ซึ่งมักได้โครงสร้างที่ข้อมูลซ้ำซ้อนและแก้ไขยากในภายหลัง

นิสิตกลุ่มหนึ่งทำโปรเจคระบบร้านกาแฟ จงเรียงลำดับงานต่อไปนี้ให้ถูกต้อง: (A) เขียน CREATE TABLE (B) สัมภาษณ์เจ้าของร้าน (C) วาด ER (D) ตรวจว่าตารางอยู่ใน 3NF (E) แปลง ER เป็นตาราง (F) เขียนรายงานยอดขายด้วย SELECT

B → C → E → D → A → F
  • ความหมายและแนวคิด
  • จงอธิบายความแตกต่างระหว่าง ข้อมูล สารสนเทศ และความรู้ พร้อมยกตัวอย่างจากระบบลงทะเบียนเรียน (Data → Information → Knowledge)

    ข้อมูล (Data) คือข้อเท็จจริงดิบที่ยังไม่ผ่านการประมวลผล เช่น แถว (5, '60001', 'A') ในตาราง enroll

    สารสนเทศ (Information) คือข้อมูลที่ผ่านการประมวลผลจนมีความหมายต่อผู้ใช้ เช่น “กลุ่มเรียน 5 มีนิสิตได้ A ร้อยละ 40” หรือเกรดเฉลี่ยของนิสิตแต่ละคน

    ความรู้ (Knowledge) คือข้อสรุปหรือรูปแบบที่ได้จากสารสนเทศและนำไปใช้ตัดสินใจได้ เช่น “นิสิตที่ได้ต่ำกว่า C ในวิชา Programming มักสอบตกวิชา Java จึงควรจัดสอนเสริม”

  • ไฟล์ Excel ที่เก็บรายชื่อนิสิตหนึ่งแผ่นถือเป็นฐานข้อมูลหรือไม่ เพราะเหตุใด (Schema + ความสัมพันธ์)

    ไม่ถือเป็นฐานข้อมูลในความหมายของวิชานี้ เป็นเพียงแฟ้มข้อมูล เพราะไม่มีโครงสร้าง (schema) ที่บังคับชนิดข้อมูล ไม่มีกฎความคงสภาพ (เช่น รหัสซ้ำได้) ไม่มีความสัมพันธ์กับข้อมูลชุดอื่น และไม่มี DBMS คอยควบคุมการเข้าถึงพร้อมกัน สิทธิ์ และการกู้คืน

  • จงอธิบายความแตกต่างระหว่าง “ฐานข้อมูล” กับ “ระบบฐานข้อมูล” (5 องค์ประกอบ)

    ฐานข้อมูล คือกลุ่มของข้อมูลที่มีความสัมพันธ์กันซึ่งจัดเก็บอย่างเป็นระบบ ส่วนระบบฐานข้อมูล คือระบบทั้งหมดที่ทำให้ใช้ฐานข้อมูลได้ ประกอบด้วย 5 องค์ประกอบ: ฮาร์ดแวร์ ซอฟต์แวร์ (DBMS + โปรแกรมประยุกต์) ข้อมูล ผู้ใช้/บุคลากร และขั้นตอนการปฏิบัติงาน

  • จงยกตัวอย่างสารสนเทศ 3 อย่างที่ได้จากตาราง enroll ของกรณีศึกษา (COUNT, AVG)

    ตัวอย่างเช่น (1) จำนวนนิสิตในแต่ละกลุ่มเรียน (2) จำนวนนิสิตที่ได้แต่ละเกรด (3) จำนวนวิชาที่นิสิตแต่ละคนลงทะเบียน

    SELECT secid, COUNT(*) AS n_student FROM enroll GROUP BY secid ORDER BY n_student DESC LIMIT 3;SELECT grade, COUNT(*) AS n FROM enroll GROUP BY grade ORDER BY grade;
  • ระบบแฟ้มข้อมูล
  • จงอธิบายปัญหาความซ้ำซ้อนและความไม่สอดคล้องของข้อมูล และอธิบายว่าทั้งสองปัญหาเกี่ยวข้องกันอย่างไร (Redundancy → Inconsistency)

    ความซ้ำซ้อน (Redundancy) คือข้อมูลเรื่องเดียวกันถูกเก็บไว้หลายที่ เปลืองพื้นที่และต้องแก้หลายจุด ความไม่สอดคล้อง (Inconsistency) คือข้อมูลเรื่องเดียวกันในแต่ละที่มีค่าไม่ตรงกัน

    ความซ้ำซ้อนเป็นสาเหตุของความไม่สอดคล้อง — เมื่อแก้ข้อมูลเพียงบางที่แต่ลืมแก้ที่อื่น ข้อมูลจึงขัดแย้งกัน เช่น ฝ่ายทะเบียนแก้สาขาของนิสิตแล้ว แต่แฟ้มของฝ่ายการเงินยังเป็นสาขาเดิม

  • ร้านค้าเก็บข้อมูลลูกค้าไว้ทั้งในแฟ้มฝ่ายขายและฝ่ายจัดส่ง จงวิเคราะห์ว่าจะเกิดปัญหาใดบ้าง อย่างน้อย 3 ปัญหา (File-processing System)
    • ความซ้ำซ้อน — ชื่อ ที่อยู่ เบอร์โทรลูกค้าถูกเก็บสองที่
    • ความไม่สอดคล้อง — ลูกค้าย้ายบ้าน แจ้งฝ่ายขายแต่ฝ่ายจัดส่งยังใช้ที่อยู่เก่า ส่งของผิดที่
    • ข้อมูลแยกกันอยู่ (Data Isolation) — ทำรายงาน “ลูกค้าที่สั่งซื้อแต่ยังไม่ได้รับของ” ต้องรวมสองแฟ้มที่รูปแบบต่างกัน
    • การเข้าถึงข้อมูลยาก — คำถามใหม่ต้องเขียนโปรแกรมใหม่ทุกครั้ง
    • ความปลอดภัย — ทั้งสองฝ่ายเห็นข้อมูลลูกค้าทั้งหมด กำหนดสิทธิ์รายคอลัมน์ไม่ได้
  • จงยกตัวอย่างปัญหา Atomicity ที่อาจเกิดขึ้นในระบบลงทะเบียนเรียน (สำเร็จทั้งหมด หรือไม่สำเร็จเลย)

    การย้ายกลุ่มเรียนประกอบด้วย 2 ขั้น คือ ลบการลงทะเบียนในกลุ่มเดิม แล้วเพิ่มในกลุ่มใหม่ ถ้าระบบล่มหลังขั้นแรก นิสิตจะไม่มีกลุ่มเรียนเลย — ระบบแฟ้มไม่มีกลไกรับประกันว่าทั้งสองขั้นต้องสำเร็จพร้อมกันหรือไม่เกิดขึ้นเลย (DBMS แก้ด้วยทรานแซกชัน บทที่ 9)

  • จงยกตัวอย่างปัญหา Concurrent Access ในระบบจองตั๋วคอนเสิร์ต (ที่นั่งสุดท้าย)

    เหลือที่นั่งสุดท้าย 1 ที่ ผู้ใช้ A และ B เปิดหน้าจองพร้อมกัน ทั้งคู่อ่านได้ว่า “ว่าง 1 ที่” แล้วกดจอง ระบบบันทึกทั้งสองรายการ — ที่นั่งเดียวถูกขายให้ 2 คน (Lost Update) เพราะไม่มีการล็อกข้อมูลขณะอ่าน-แก้ไข

  • เหตุใดระบบแฟ้มข้อมูลจึงกำหนดสิทธิ์ให้ผู้ใช้เห็นข้อมูลเฉพาะบางคอลัมน์ได้ยาก (Security Problem)

    ระบบปฏิบัติการกำหนดสิทธิ์ได้ระดับทั้งแฟ้ม (อ่าน/เขียน/ไม่ให้เข้า) ถ้าผู้ใช้เปิดแฟ้มได้ก็เห็นทุกคอลัมน์ การซ่อนบางคอลัมน์ต้องแยกแฟ้มหรือเขียนโปรแกรมกรองเอง ซึ่งทำให้ข้อมูลซ้ำซ้อนยิ่งขึ้น ส่วน DBMS กำหนดสิทธิ์รายตาราง รายคอลัมน์ และผ่านวิวได้

  • DBMS และองค์ประกอบ
  • จงอธิบายหน้าที่ของ DBMS อย่างน้อย 5 ข้อ พร้อมยกตัวอย่างประกอบแต่ละข้อ (DDL, DML, Integrity, Security, Concurrency, Recovery)
    • นิยามข้อมูล (DDL) — สร้างตาราง student ด้วย CREATE TABLE
    • จัดการข้อมูล (DML) — INSERT / UPDATE / DELETE / SELECT การลงทะเบียน
    • รักษาความถูกต้อง (Integrity) — ไม่ยอมให้เกรดเป็น 'Z' (CHECK) หรือลงทะเบียน section ที่ไม่มีอยู่ (FK)
    • ความปลอดภัย (Security) — ให้อาจารย์แก้ได้เฉพาะคอลัมน์ grade
    • ควบคุมการทำงานพร้อมกัน (Concurrency) — นิสิต 2 คนแย่งที่นั่งสุดท้ายไม่เกินจำนวนที่รับ
    • สำรองและกู้คืน (Backup & Recovery) — ไฟดับระหว่างบันทึกเกรด ข้อมูลกลับสู่สภาพที่ถูกต้อง
    • พจนานุกรมข้อมูล — เก็บ metadata ของทุกตาราง
  • Metadata และ Data Dictionary คืออะไร ยกตัวอย่าง metadata ของตาราง student (ชื่อคอลัมน์ ชนิดข้อมูล)

    Metadata คือ “ข้อมูลที่อธิบายข้อมูล” ส่วน Data Dictionary คือที่เก็บ metadata ทั้งหมดของฐานข้อมูล (ใน MySQL คือ information_schema) ตัวอย่าง metadata ของ student: ชื่อคอลัมน์ ชนิดข้อมูล ความยาว ค่าว่างได้หรือไม่ คีย์หลัก

    SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_KEY FROM information_schema.COLUMNS WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'student' ORDER BY ORDINAL_POSITION;
  • จงระบุบทบาทของผู้บริหารฐานข้อมูล (DBA) อย่างน้อย 5 ข้อ และอธิบายว่าเหตุใดองค์กรขนาดใหญ่จึงต้องมีตำแหน่งนี้ (สิทธิ์ สำรอง ปรับแต่ง)

    บทบาทของ DBA: (1) ติดตั้งและดูแล DBMS (2) สร้างบัญชีผู้ใช้และกำหนดสิทธิ์ (3) สำรองข้อมูลและกู้คืน (4) ตรวจสอบและปรับประสิทธิภาพ เช่น สร้างดัชนี (5) กำหนดมาตรฐานและนโยบายความปลอดภัย (6) วางแผนความจุและการขยายระบบ

    องค์กรขนาดใหญ่มีข้อมูลจำนวนมาก ผู้ใช้หลายกลุ่ม และข้อมูลเป็นทรัพย์สินสำคัญ ความผิดพลาดหรือข้อมูลรั่วไหลมีผลกระทบสูง จึงต้องมีผู้รับผิดชอบโดยตรง

  • จงเปรียบเทียบหน้าที่ของ Database Designer, System Analyst และ Application Programmer (ตารางบุคลากร)
    • System Analyst — ศึกษาความต้องการของผู้ใช้ วิเคราะห์ระบบงาน และกำหนดว่าระบบต้องทำอะไร
    • Database Designer — ออกแบบโครงสร้างฐานข้อมูล (ER, ตาราง, คีย์, นอร์มัลไลเซชัน) ให้ตอบความต้องการนั้น
    • Application Programmer — เขียนโปรแกรมประยุกต์ (หน้าจอ รายงาน) ที่ใช้งานฐานข้อมูลผ่าน SQL
  • จงเลือก DBMS ที่เหมาะสมสำหรับ
    (ก) แอปมือถือออฟไลน์
    (ข) เว็บร้านค้าขนาดเล็ก
    (ค) ระบบธนาคาร พร้อมเหตุผล (SQLite, MySQL, Oracle)

    (ก) SQLite — ฝังในแอปได้ ไม่ต้องมีเซิร์ฟเวอร์ ไฟล์เดียว
    (ข) MySQL / MariaDB / PostgreSQL — ฟรี โฮสติ้งรองรับทั่วไป ใช้กับเว็บได้ดี
    (ค) Oracle / IBM Db2 / SQL Server — รองรับธุรกรรมปริมาณมาก ความเสถียรสูง มีระบบสำรองและความปลอดภัยระดับองค์กร พร้อมบริการสนับสนุน

  • สถาปัตยกรรมและแบบจำลองข้อมูล
  • จงอธิบายสถาปัตยกรรม 3 ระดับตามมาตรฐาน ANSI-SPARC พร้อมยกตัวอย่างจากระบบลงทะเบียน (External, Conceptual, Internal)
    • External Level — มุมมองของผู้ใช้แต่ละกลุ่ม เช่น นิสิตเห็นเฉพาะผลการเรียนของตน อาจารย์เห็นรายชื่อนิสิตในกลุ่มที่สอน
    • Conceptual Level — โครงสร้างทั้งหมดของฐานข้อมูล: ตาราง student, subject, lecturer, section, enroll ความสัมพันธ์ และกฎ
    • Internal Level — วิธีจัดเก็บจริงบนดิสก์ เช่น ไฟล์ของ InnoDB ดัชนี B-Tree
  • จงอธิบายความแตกต่างระหว่าง Logical Data Independence และ Physical Data Independence (เปลี่ยนระดับไหน ไม่กระทบระดับไหน)

    Logical Data Independence — เปลี่ยนระดับ Conceptual (เช่น เพิ่มคอลัมน์ email ใน student) โดยไม่กระทบระดับ External (วิว/โปรแกรมเดิมยังใช้ได้)

    Physical Data Independence — เปลี่ยนระดับ Internal (เช่น สร้างดัชนี ย้ายไฟล์ไปดิสก์ใหม่) โดยไม่กระทบระดับ Conceptual ทำได้ง่ายกว่าแบบแรก

  • หากมหาวิทยาลัยต้องการให้อาจารย์เห็นเฉพาะรายชื่อนิสิตในกลุ่มเรียนที่ตนสอน การออกแบบนี้อยู่ระดับใด เพราะเหตุใด (View)

    External Level — เป็นการกำหนดมุมมองเฉพาะกลุ่มผู้ใช้ ซึ่งใน SQL ทำได้ด้วยวิว (บทที่ 7) เช่น วิวที่ JOIN section กับ enroll และกรองด้วยรหัสอาจารย์

  • จงอธิบายการทำงานของสถาปัตยกรรม Client-Server เมื่อนิสิตใช้ DBeaver เชื่อมต่อเซิร์ฟเวอร์ 202.28.34.202 (client / server)

    DBeaver บนเครื่องนิสิตเป็น Client ส่งคำสั่ง SQL ผ่านเครือข่ายไปยัง MySQL Server ที่ 202.28.34.202 พอร์ต 3306 ซึ่งเป็น Server ทำหน้าที่ตรวจสิทธิ์ ประมวลผลคำสั่งกับข้อมูลที่เก็บอยู่บนเซิร์ฟเวอร์ แล้วส่งผลลัพธ์กลับมาให้ DBeaver แสดง — ข้อมูลอยู่ที่เดียว ผู้ใช้หลายคนเชื่อมต่อพร้อมกันได้

  • จงเปรียบเทียบแบบจำลองข้อมูลแบบลำดับชั้น เครือข่าย และเชิงสัมพันธ์ ในแง่โครงสร้างและข้อจำกัด (ต้นไม้ / กราฟ / ตาราง)
    • ลำดับชั้น (Hierarchical) — โครงสร้างต้นไม้ ลูก 1 ตัวมีพ่อได้ตัวเดียว แทน M:N ไม่ได้โดยตรง ต้องเก็บซ้ำ ค้นหาต้องไล่จากราก
    • เครือข่าย (Network) — โครงสร้างกราฟ ลูกมีพ่อได้หลายตัว แทน M:N ได้ แต่ซับซ้อน โปรแกรมต้องรู้เส้นทางการเชื่อม (pointer)
    • เชิงสัมพันธ์ (Relational) — เก็บเป็นตาราง เชื่อมกันด้วยค่าของคีย์ ใช้ SQL ถามได้โดยไม่ต้องรู้โครงสร้างจัดเก็บ ข้อจำกัดคือการ JOIN ข้อมูลจำนวนมากอาจช้า และไม่เหมาะกับข้อมูลไม่มีโครงสร้าง
  • จงเปรียบเทียบข้อดีและข้อจำกัดของฐานข้อมูลเชิงสัมพันธ์กับ NoSQL อย่างละ 3 ข้อ (ACID vs Scale-out)

    Relational — ข้อดี: รองรับ ACID, มีกฎความคงสภาพ, SQL เป็นมาตรฐาน · ข้อจำกัด: โครงสร้างตายตัว, ขยายแบบกระจายหลายเครื่องยาก, ไม่เหมาะกับข้อมูลไม่มีโครงสร้าง

    NoSQL — ข้อดี: โครงสร้างยืดหยุ่น, ขยายแบบ Scale-out ง่าย, รองรับข้อมูลปริมาณมาก/ความเร็วสูง · ข้อจำกัด: มักผ่อนปรนความสอดคล้อง (eventual consistency), JOIN ทำได้จำกัด, ไม่มีภาษามาตรฐานเดียว

  • จงจับคู่ศัพท์ Relation, Tuple, Attribute, Domain กับคำที่ใช้ในทางปฏิบัติ พร้อมตัวอย่างจากตาราง lecturer (ตาราง แถว คอลัมน์)

    Relation = ตาราง (lecturer) · Tuple = แถว/ระเบียน (t01, Peter Parker, …) · Attribute = คอลัมน์ (salary) · Domain = ขอบเขตค่าที่เป็นไปได้ ของคอลัมน์ (salary เป็นจำนวนเต็มบวก)

  • วงจรการพัฒนาและการประยุกต์
  • จงเรียงลำดับขั้นตอนในวงจรการพัฒนาระบบฐานข้อมูล และระบุผลผลิตของแต่ละขั้น (Requirement → ER → Table → Normalize → SQL)

    (1) รวบรวมและวิเคราะห์ความต้องการ → เอกสารความต้องการ (2) ออกแบบเชิงแนวคิด → แผนภาพ ER (3) ออกแบบเชิงตรรกะ → โครงสร้างตารางที่ผ่านนอร์มัลไลเซชัน (4) ออกแบบเชิงกายภาพ → ชนิดข้อมูล ดัชนี (5) สร้างและนำไปใช้ → สคริปต์ SQL ฐานข้อมูลจริง (6) ทดสอบ บำรุงรักษา และปรับปรุง

  • เหตุใดการข้ามขั้นตอนออกแบบแล้วสร้างตารางทันทีจึงเป็นความผิดพลาดที่พบบ่อย ยกตัวอย่างผลเสีย (ซ้ำซ้อน แก้ยาก)

    เพราะดูเหมือนเร็ว แต่ได้ตารางที่ไม่ผ่านนอร์มัลไลเซชัน เช่น เก็บชื่อวิชาและหน่วยกิตซ้ำในทุกแถวของการลงทะเบียน → แก้ชื่อวิชาต้องแก้หลายแถว (Update Anomaly) ลบการลงทะเบียนสุดท้ายแล้วข้อมูลวิชาหายไปด้วย (Deletion Anomaly) และเมื่อมีข้อมูลแล้วการแก้โครงสร้างทำได้ยากและเสี่ยง

  • เลือกระบบงานที่คุ้นเคย (เช่น ยืม-คืนหนังสือ) แล้วระบุข้อมูลที่ต้องเก็บ กลุ่มผู้ใช้ และข้อมูลที่แต่ละกลุ่มควรเห็น (External view แต่ละกลุ่ม)

    ตัวอย่างระบบห้องสมุด — ข้อมูล: สมาชิก หนังสือ หมวดหมู่ ผู้แต่ง การยืม-คืน ค่าปรับ

    • สมาชิก — ค้นหนังสือ ดูสถานะว่าง ประวัติการยืมและค่าปรับของตนเอง
    • บรรณารักษ์ — ข้อมูลหนังสือและสมาชิกทั้งหมด บันทึกยืม-คืน ค่าปรับ
    • ผู้บริหาร — รายงานสรุป เช่น หนังสือยอดนิยม จำนวนการยืมต่อเดือน (ไม่จำเป็นต้องเห็นข้อมูลส่วนตัวของสมาชิก)
