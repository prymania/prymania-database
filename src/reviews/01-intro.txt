# คำถามท้ายบท + เฉลย — ดูรูปแบบที่ apply_reviews.py
## ความหมายและแนวคิด
จงอธิบายความแตกต่างระหว่าง ข้อมูล สารสนเทศ และความรู้ พร้อมยกตัวอย่างจากระบบลงทะเบียนเรียน || Data → Information → Knowledge
A: <b>ข้อมูล (Data)</b> คือข้อเท็จจริงดิบที่ยังไม่ผ่านการประมวลผล เช่น แถว `(5, '60001', 'A')` ในตาราง enroll
A: <b>สารสนเทศ (Information)</b> คือข้อมูลที่ผ่านการประมวลผลจนมีความหมายต่อผู้ใช้ เช่น “กลุ่มเรียน 5 มีนิสิตได้ A ร้อยละ 40” หรือเกรดเฉลี่ยของนิสิตแต่ละคน
A: <b>ความรู้ (Knowledge)</b> คือข้อสรุปหรือรูปแบบที่ได้จากสารสนเทศและนำไปใช้ตัดสินใจได้ เช่น “นิสิตที่ได้ต่ำกว่า C ในวิชา Programming มักสอบตกวิชา Java จึงควรจัดสอนเสริม”
ไฟล์ Excel ที่เก็บรายชื่อนิสิตหนึ่งแผ่นถือเป็นฐานข้อมูลหรือไม่ เพราะเหตุใด || Schema + ความสัมพันธ์
A: ไม่ถือเป็นฐานข้อมูลในความหมายของวิชานี้ เป็นเพียง<b>แฟ้มข้อมูล</b> เพราะไม่มีโครงสร้าง (schema) ที่บังคับชนิดข้อมูล ไม่มีกฎความคงสภาพ (เช่น รหัสซ้ำได้) ไม่มีความสัมพันธ์กับข้อมูลชุดอื่น และไม่มี DBMS คอยควบคุมการเข้าถึงพร้อมกัน สิทธิ์ และการกู้คืน
จงอธิบายความแตกต่างระหว่าง “ฐานข้อมูล” กับ “ระบบฐานข้อมูล” || 5 องค์ประกอบ
A: <b>ฐานข้อมูล</b> คือกลุ่มของข้อมูลที่มีความสัมพันธ์กันซึ่งจัดเก็บอย่างเป็นระบบ ส่วน<b>ระบบฐานข้อมูล</b> คือระบบทั้งหมดที่ทำให้ใช้ฐานข้อมูลได้ ประกอบด้วย 5 องค์ประกอบ: ฮาร์ดแวร์ ซอฟต์แวร์ (DBMS + โปรแกรมประยุกต์) ข้อมูล ผู้ใช้/บุคลากร และขั้นตอนการปฏิบัติงาน
จงยกตัวอย่างสารสนเทศ 3 อย่างที่ได้จากตาราง enroll ของกรณีศึกษา || COUNT, AVG
A: ตัวอย่างเช่น (1) จำนวนนิสิตในแต่ละกลุ่มเรียน (2) จำนวนนิสิตที่ได้แต่ละเกรด (3) จำนวนวิชาที่นิสิตแต่ละคนลงทะเบียน
```run
SELECT secid, COUNT(*) AS n_student FROM enroll GROUP BY secid ORDER BY n_student DESC LIMIT 3;
```
```run
SELECT grade, COUNT(*) AS n FROM enroll GROUP BY grade ORDER BY grade;
```
## ระบบแฟ้มข้อมูล
จงอธิบายปัญหาความซ้ำซ้อนและความไม่สอดคล้องของข้อมูล และอธิบายว่าทั้งสองปัญหาเกี่ยวข้องกันอย่างไร || Redundancy → Inconsistency
A: <b>ความซ้ำซ้อน (Redundancy)</b> คือข้อมูลเรื่องเดียวกันถูกเก็บไว้หลายที่ เปลืองพื้นที่และต้องแก้หลายจุด <b>ความไม่สอดคล้อง (Inconsistency)</b> คือข้อมูลเรื่องเดียวกันในแต่ละที่มีค่าไม่ตรงกัน
A: ความซ้ำซ้อนเป็น<b>สาเหตุ</b>ของความไม่สอดคล้อง — เมื่อแก้ข้อมูลเพียงบางที่แต่ลืมแก้ที่อื่น ข้อมูลจึงขัดแย้งกัน เช่น ฝ่ายทะเบียนแก้สาขาของนิสิตแล้ว แต่แฟ้มของฝ่ายการเงินยังเป็นสาขาเดิม
ร้านค้าเก็บข้อมูลลูกค้าไว้ทั้งในแฟ้มฝ่ายขายและฝ่ายจัดส่ง จงวิเคราะห์ว่าจะเกิดปัญหาใดบ้าง อย่างน้อย 3 ปัญหา || File-processing System
A- <b>ความซ้ำซ้อน</b> — ชื่อ ที่อยู่ เบอร์โทรลูกค้าถูกเก็บสองที่
A- <b>ความไม่สอดคล้อง</b> — ลูกค้าย้ายบ้าน แจ้งฝ่ายขายแต่ฝ่ายจัดส่งยังใช้ที่อยู่เก่า ส่งของผิดที่
A- <b>ข้อมูลแยกกันอยู่ (Data Isolation)</b> — ทำรายงาน “ลูกค้าที่สั่งซื้อแต่ยังไม่ได้รับของ” ต้องรวมสองแฟ้มที่รูปแบบต่างกัน
A- <b>การเข้าถึงข้อมูลยาก</b> — คำถามใหม่ต้องเขียนโปรแกรมใหม่ทุกครั้ง
A- <b>ความปลอดภัย</b> — ทั้งสองฝ่ายเห็นข้อมูลลูกค้าทั้งหมด กำหนดสิทธิ์รายคอลัมน์ไม่ได้
จงยกตัวอย่างปัญหา Atomicity ที่อาจเกิดขึ้นในระบบลงทะเบียนเรียน || สำเร็จทั้งหมด หรือไม่สำเร็จเลย
A: การย้ายกลุ่มเรียนประกอบด้วย 2 ขั้น คือ ลบการลงทะเบียนในกลุ่มเดิม แล้วเพิ่มในกลุ่มใหม่ ถ้าระบบล่มหลังขั้นแรก นิสิตจะ<b>ไม่มีกลุ่มเรียนเลย</b> — ระบบแฟ้มไม่มีกลไกรับประกันว่าทั้งสองขั้นต้องสำเร็จพร้อมกันหรือไม่เกิดขึ้นเลย (DBMS แก้ด้วยทรานแซกชัน บทที่ 9)
จงยกตัวอย่างปัญหา Concurrent Access ในระบบจองตั๋วคอนเสิร์ต || ที่นั่งสุดท้าย
A: เหลือที่นั่งสุดท้าย 1 ที่ ผู้ใช้ A และ B เปิดหน้าจองพร้อมกัน ทั้งคู่อ่านได้ว่า “ว่าง 1 ที่” แล้วกดจอง ระบบบันทึกทั้งสองรายการ — ที่นั่งเดียวถูกขายให้ 2 คน (Lost Update) เพราะไม่มีการล็อกข้อมูลขณะอ่าน-แก้ไข
เหตุใดระบบแฟ้มข้อมูลจึงกำหนดสิทธิ์ให้ผู้ใช้เห็นข้อมูลเฉพาะบางคอลัมน์ได้ยาก || Security Problem
A: ระบบปฏิบัติการกำหนดสิทธิ์ได้ระดับ<b>ทั้งแฟ้ม</b> (อ่าน/เขียน/ไม่ให้เข้า) ถ้าผู้ใช้เปิดแฟ้มได้ก็เห็นทุกคอลัมน์ การซ่อนบางคอลัมน์ต้องแยกแฟ้มหรือเขียนโปรแกรมกรองเอง ซึ่งทำให้ข้อมูลซ้ำซ้อนยิ่งขึ้น ส่วน DBMS กำหนดสิทธิ์รายตาราง รายคอลัมน์ และผ่านวิวได้
## DBMS และองค์ประกอบ
จงอธิบายหน้าที่ของ DBMS อย่างน้อย 5 ข้อ พร้อมยกตัวอย่างประกอบแต่ละข้อ || DDL, DML, Integrity, Security, Concurrency, Recovery
A- <b>นิยามข้อมูล (DDL)</b> — สร้างตาราง student ด้วย CREATE TABLE
A- <b>จัดการข้อมูล (DML)</b> — INSERT / UPDATE / DELETE / SELECT การลงทะเบียน
A- <b>รักษาความถูกต้อง (Integrity)</b> — ไม่ยอมให้เกรดเป็น 'Z' (CHECK) หรือลงทะเบียน section ที่ไม่มีอยู่ (FK)
A- <b>ความปลอดภัย (Security)</b> — ให้อาจารย์แก้ได้เฉพาะคอลัมน์ grade
A- <b>ควบคุมการทำงานพร้อมกัน (Concurrency)</b> — นิสิต 2 คนแย่งที่นั่งสุดท้ายไม่เกินจำนวนที่รับ
A- <b>สำรองและกู้คืน (Backup & Recovery)</b> — ไฟดับระหว่างบันทึกเกรด ข้อมูลกลับสู่สภาพที่ถูกต้อง
A- <b>พจนานุกรมข้อมูล</b> — เก็บ metadata ของทุกตาราง
Metadata และ Data Dictionary คืออะไร ยกตัวอย่าง metadata ของตาราง student || ชื่อคอลัมน์ ชนิดข้อมูล
A: <b>Metadata</b> คือ “ข้อมูลที่อธิบายข้อมูล” ส่วน <b>Data Dictionary</b> คือที่เก็บ metadata ทั้งหมดของฐานข้อมูล (ใน MySQL คือ information_schema) ตัวอย่าง metadata ของ student: ชื่อคอลัมน์ ชนิดข้อมูล ความยาว ค่าว่างได้หรือไม่ คีย์หลัก
```run
SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_KEY
FROM   information_schema.COLUMNS
WHERE  TABLE_SCHEMA = DATABASE() AND TABLE_NAME = 'student'
ORDER  BY ORDINAL_POSITION;
```
จงระบุบทบาทของผู้บริหารฐานข้อมูล (DBA) อย่างน้อย 5 ข้อ และอธิบายว่าเหตุใดองค์กรขนาดใหญ่จึงต้องมีตำแหน่งนี้ || สิทธิ์ สำรอง ปรับแต่ง
A: บทบาทของ DBA: (1) ติดตั้งและดูแล DBMS (2) สร้างบัญชีผู้ใช้และกำหนดสิทธิ์ (3) สำรองข้อมูลและกู้คืน (4) ตรวจสอบและปรับประสิทธิภาพ เช่น สร้างดัชนี (5) กำหนดมาตรฐานและนโยบายความปลอดภัย (6) วางแผนความจุและการขยายระบบ
A: องค์กรขนาดใหญ่มีข้อมูลจำนวนมาก ผู้ใช้หลายกลุ่ม และข้อมูลเป็นทรัพย์สินสำคัญ ความผิดพลาดหรือข้อมูลรั่วไหลมีผลกระทบสูง จึงต้องมีผู้รับผิดชอบโดยตรง
จงเปรียบเทียบหน้าที่ของ Database Designer, System Analyst และ Application Programmer || ตารางบุคลากร
A- <b>System Analyst</b> — ศึกษาความต้องการของผู้ใช้ วิเคราะห์ระบบงาน และกำหนดว่าระบบต้องทำอะไร
A- <b>Database Designer</b> — ออกแบบโครงสร้างฐานข้อมูล (ER, ตาราง, คีย์, นอร์มัลไลเซชัน) ให้ตอบความต้องการนั้น
A- <b>Application Programmer</b> — เขียนโปรแกรมประยุกต์ (หน้าจอ รายงาน) ที่ใช้งานฐานข้อมูลผ่าน SQL
จงเลือก DBMS ที่เหมาะสมสำหรับ (ก) แอปมือถือออฟไลน์ (ข) เว็บร้านค้าขนาดเล็ก (ค) ระบบธนาคาร พร้อมเหตุผล || SQLite, MySQL, Oracle
A: (ก) <b>SQLite</b> — ฝังในแอปได้ ไม่ต้องมีเซิร์ฟเวอร์ ไฟล์เดียว<br>(ข) <b>MySQL / MariaDB / PostgreSQL</b> — ฟรี โฮสติ้งรองรับทั่วไป ใช้กับเว็บได้ดี<br>(ค) <b>Oracle / IBM Db2 / SQL Server</b> — รองรับธุรกรรมปริมาณมาก ความเสถียรสูง มีระบบสำรองและความปลอดภัยระดับองค์กร พร้อมบริการสนับสนุน
## สถาปัตยกรรมและแบบจำลองข้อมูล
จงอธิบายสถาปัตยกรรม 3 ระดับตามมาตรฐาน ANSI-SPARC พร้อมยกตัวอย่างจากระบบลงทะเบียน || External, Conceptual, Internal
A- <b>External Level</b> — มุมมองของผู้ใช้แต่ละกลุ่ม เช่น นิสิตเห็นเฉพาะผลการเรียนของตน อาจารย์เห็นรายชื่อนิสิตในกลุ่มที่สอน
A- <b>Conceptual Level</b> — โครงสร้างทั้งหมดของฐานข้อมูล: ตาราง student, subject, lecturer, section, enroll ความสัมพันธ์ และกฎ
A- <b>Internal Level</b> — วิธีจัดเก็บจริงบนดิสก์ เช่น ไฟล์ของ InnoDB ดัชนี B-Tree
จงอธิบายความแตกต่างระหว่าง Logical Data Independence และ Physical Data Independence || เปลี่ยนระดับไหน ไม่กระทบระดับไหน
A: <b>Logical Data Independence</b> — เปลี่ยนระดับ Conceptual (เช่น เพิ่มคอลัมน์ email ใน student) โดยไม่กระทบระดับ External (วิว/โปรแกรมเดิมยังใช้ได้)
A: <b>Physical Data Independence</b> — เปลี่ยนระดับ Internal (เช่น สร้างดัชนี ย้ายไฟล์ไปดิสก์ใหม่) โดยไม่กระทบระดับ Conceptual ทำได้ง่ายกว่าแบบแรก
หากมหาวิทยาลัยต้องการให้อาจารย์เห็นเฉพาะรายชื่อนิสิตในกลุ่มเรียนที่ตนสอน การออกแบบนี้อยู่ระดับใด เพราะเหตุใด || View
A: <b>External Level</b> — เป็นการกำหนดมุมมองเฉพาะกลุ่มผู้ใช้ ซึ่งใน SQL ทำได้ด้วย<b>วิว</b> (บทที่ 7) เช่น วิวที่ JOIN section กับ enroll และกรองด้วยรหัสอาจารย์
จงอธิบายการทำงานของสถาปัตยกรรม Client-Server เมื่อนิสิตใช้ DBeaver เชื่อมต่อเซิร์ฟเวอร์ 202.28.34.202 || client / server
A: DBeaver บนเครื่องนิสิตเป็น <b>Client</b> ส่งคำสั่ง SQL ผ่านเครือข่ายไปยัง MySQL Server ที่ 202.28.34.202 พอร์ต 3306 ซึ่งเป็น <b>Server</b> ทำหน้าที่ตรวจสิทธิ์ ประมวลผลคำสั่งกับข้อมูลที่เก็บอยู่บนเซิร์ฟเวอร์ แล้วส่งผลลัพธ์กลับมาให้ DBeaver แสดง — ข้อมูลอยู่ที่เดียว ผู้ใช้หลายคนเชื่อมต่อพร้อมกันได้
จงเปรียบเทียบแบบจำลองข้อมูลแบบลำดับชั้น เครือข่าย และเชิงสัมพันธ์ ในแง่โครงสร้างและข้อจำกัด || ต้นไม้ / กราฟ / ตาราง
A- <b>ลำดับชั้น (Hierarchical)</b> — โครงสร้างต้นไม้ ลูก 1 ตัวมีพ่อได้ตัวเดียว แทน M:N ไม่ได้โดยตรง ต้องเก็บซ้ำ ค้นหาต้องไล่จากราก
A- <b>เครือข่าย (Network)</b> — โครงสร้างกราฟ ลูกมีพ่อได้หลายตัว แทน M:N ได้ แต่ซับซ้อน โปรแกรมต้องรู้เส้นทางการเชื่อม (pointer)
A- <b>เชิงสัมพันธ์ (Relational)</b> — เก็บเป็นตาราง เชื่อมกันด้วยค่าของคีย์ ใช้ SQL ถามได้โดยไม่ต้องรู้โครงสร้างจัดเก็บ ข้อจำกัดคือการ JOIN ข้อมูลจำนวนมากอาจช้า และไม่เหมาะกับข้อมูลไม่มีโครงสร้าง
จงเปรียบเทียบข้อดีและข้อจำกัดของฐานข้อมูลเชิงสัมพันธ์กับ NoSQL อย่างละ 3 ข้อ || ACID vs Scale-out
A: <b>Relational</b> — ข้อดี: รองรับ ACID, มีกฎความคงสภาพ, SQL เป็นมาตรฐาน · ข้อจำกัด: โครงสร้างตายตัว, ขยายแบบกระจายหลายเครื่องยาก, ไม่เหมาะกับข้อมูลไม่มีโครงสร้าง
A: <b>NoSQL</b> — ข้อดี: โครงสร้างยืดหยุ่น, ขยายแบบ Scale-out ง่าย, รองรับข้อมูลปริมาณมาก/ความเร็วสูง · ข้อจำกัด: มักผ่อนปรนความสอดคล้อง (eventual consistency), JOIN ทำได้จำกัด, ไม่มีภาษามาตรฐานเดียว
จงจับคู่ศัพท์ Relation, Tuple, Attribute, Domain กับคำที่ใช้ในทางปฏิบัติ พร้อมตัวอย่างจากตาราง lecturer || ตาราง แถว คอลัมน์
A: Relation = <b>ตาราง</b> (lecturer) · Tuple = <b>แถว/ระเบียน</b> (t01, Peter Parker, …) · Attribute = <b>คอลัมน์</b> (salary) · Domain = <b>ขอบเขตค่าที่เป็นไปได้</b> ของคอลัมน์ (salary เป็นจำนวนเต็มบวก)
## วงจรการพัฒนาและการประยุกต์
จงเรียงลำดับขั้นตอนในวงจรการพัฒนาระบบฐานข้อมูล และระบุผลผลิตของแต่ละขั้น || Requirement → ER → Table → Normalize → SQL
A: (1) รวบรวมและวิเคราะห์ความต้องการ → เอกสารความต้องการ (2) ออกแบบเชิงแนวคิด → แผนภาพ ER (3) ออกแบบเชิงตรรกะ → โครงสร้างตารางที่ผ่านนอร์มัลไลเซชัน (4) ออกแบบเชิงกายภาพ → ชนิดข้อมูล ดัชนี (5) สร้างและนำไปใช้ → สคริปต์ SQL ฐานข้อมูลจริง (6) ทดสอบ บำรุงรักษา และปรับปรุง
เหตุใดการข้ามขั้นตอนออกแบบแล้วสร้างตารางทันทีจึงเป็นความผิดพลาดที่พบบ่อย ยกตัวอย่างผลเสีย || ซ้ำซ้อน แก้ยาก
A: เพราะดูเหมือนเร็ว แต่ได้ตารางที่ไม่ผ่านนอร์มัลไลเซชัน เช่น เก็บชื่อวิชาและหน่วยกิตซ้ำในทุกแถวของการลงทะเบียน → แก้ชื่อวิชาต้องแก้หลายแถว (Update Anomaly) ลบการลงทะเบียนสุดท้ายแล้วข้อมูลวิชาหายไปด้วย (Deletion Anomaly) และเมื่อมีข้อมูลแล้วการแก้โครงสร้างทำได้ยากและเสี่ยง
เลือกระบบงานที่คุ้นเคย (เช่น ยืม-คืนหนังสือ) แล้วระบุข้อมูลที่ต้องเก็บ กลุ่มผู้ใช้ และข้อมูลที่แต่ละกลุ่มควรเห็น || External view แต่ละกลุ่ม
A: ตัวอย่างระบบห้องสมุด — ข้อมูล: สมาชิก หนังสือ หมวดหมู่ ผู้แต่ง การยืม-คืน ค่าปรับ
A- <b>สมาชิก</b> — ค้นหนังสือ ดูสถานะว่าง ประวัติการยืมและค่าปรับของตนเอง
A- <b>บรรณารักษ์</b> — ข้อมูลหนังสือและสมาชิกทั้งหมด บันทึกยืม-คืน ค่าปรับ
A- <b>ผู้บริหาร</b> — รายงานสรุป เช่น หนังสือยอดนิยม จำนวนการยืมต่อเดือน (ไม่จำเป็นต้องเห็นข้อมูลส่วนตัวของสมาชิก)
